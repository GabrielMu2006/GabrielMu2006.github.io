New Model Test 是一个公开记录新模型评测过程的档案仓库：每个阶段保存当期使用的原始 prompt、模型交付物、运行与测试方法、视觉证据以及复盘报告。它的目标不是只展示最好看的结果，而是尽量保留从任务输入到成果、验证和问题分析的完整链路。当前内容为 Phase 1，用 15 个任务评估 `DeepSeek-V4.1-Flash-Exp-0910`。

## 当前阶段

- Phase 1 已完成：15 个任务均满足原始 prompt 的核心要求，仓库内人工与自动化评估给出的综合分为 93.6/100。README 明确说明该分数用于总结本次测试，不应视为跨模型的通用排行榜分数。
- 评测覆盖 SVG 视觉生成与精确约束遵循、单文件网页 / 游戏 / 创作工具、复杂交互式 Web 应用、几何与计算、数据状态与错误处理，以及响应式设计、可访问性、视觉完成度和自动化测试。
- 任务 01–10 的主要成果零依赖，直接打开 `index.html` 或 SVG 即可查看；任务 11–15 带项目内测试，多数不需要 `npm install`，Node.js 主要用于执行测试。
- 关键文档：`15_TEST_PROMPTS_BILINGUAL.md`（15 条原始 prompt 与双语验收内容）、阶段索引 `DeepSeek-V4.1-Flash-Exp-0910_DSH/README.md`，以及 `Reviews/` 下的统计复盘、质量评估与人工评价。

## 工程与现状

- 仓库按阶段组织：根 `README.md` 维护阶段索引，`DeepSeek-V4.1-Flash-Exp-0910_DSH/` 为 Phase 1，15 个任务各自独立成目录并带任务 README；后续阶段以新的同级目录加入。
- Phase 1 共 15 个项目、193 个项目文件，约 36 MB，外部依赖为零（无 npm 包、无 CDN、无外部图片或字体）。
- 已知限制：task-13 的部分浏览器验证脚本仍包含原评测机器上的 Playwright 缓存路径，逻辑单元测试可直接运行，但跨机器执行浏览器审计前需要调整路径或通过 `PW` 环境变量提供模块位置。
- 仓库当前未标注开源许可证。README 声明其中的品牌、银行、账户、利率、人物和产品均为测试或演示内容，Meridian Bank 为虚构机构，不提供真实金融服务。

## 设计原则

**保留完整链路。** 每个任务同时留下原始 prompt、交付物、测试方法和视觉证据，任何结论都能回溯到产生它的任务与检查项。

**可复现优先。** 可复现测试保存在仓库内，而不只引用临时脚本；新增阶段要求不覆盖已有结果，并同时记录通过项、失败项、重试和已知限制。

**诚实标注边界。** 综合分被限定为本次测试的自评，不作为跨模型榜单；已知问题（如 task-13 的 Playwright 路径与统一验证的服务编排）直接写在 README 里。

**Insight.** 这个仓库真正有意思的地方不是"15 个任务全部完成"，而是它把模型评测做成了可审计的档案：prompt、成果、测试与复盘分层存放，扣分理由和已知限制与通过项一起公开。对一个评测仓库来说，这种"连证据带局限一起归档"的做法，比一份漂亮的成绩单更能说明模型真实的能力边界。
